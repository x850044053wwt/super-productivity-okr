# Super Productivity OKR

独立维护的 Super Productivity 插件：按双月周期管理目标（O）及其关键结果（KR），支持新增、删除、拖拽、上下排序、把目标结转到相邻周期，以及对已结束周期的目标自我打分。

## 开发与打包

需要 Node.js 18+。没有 npm 依赖，无需先安装依赖。打包 ZIP 另外需要系统 `zip` 命令（macOS 自带；Linux 可通过包管理器安装）。

```sh
npm test
npm run build
npm run package
```

- `dist/`：可运行的插件文件。
- `releases/okr-<version>.zip`：可导入 Super Productivity 的插件压缩包。
- 构建只写入当前仓库，不依赖或修改主应用目录。

## 主应用集成

主应用通过 Git 子模块 `packages/plugin-dev/okr` 固定此仓库的一个提交。主应用构建脚本负责把 `dist/` 复制到 `src/assets/bundled-plugins/okr/`，不要直接编辑生成文件。

修改插件后，先在本仓库提交，再更新主项目的子模块引用。初始化子模块和具体更新步骤见主项目 `docs/okr-plugin.md`。

ZIP 适用于未内置同名插件的宿主。当前主应用保留 `okr` 为内置插件 ID，会拒绝上传同 ID ZIP；更新内置 OKR 应通过子模块后重新构建主应用。不要改插件 ID 来绕过限制，否则已有同步数据不会自动迁移。

## 数据与版本

O、KR 及顺序使用现有插件持久化接口保存为一份文档，支持离线、应用备份和跨设备同步。多设备并发修改按整份文档最后写入覆盖，不逐条合并。

### 双月周期

- 周期按固定自然月划分：1–2 月、3–4 月、5–6 月、7–8 月、9–10 月、11–12 月，跨年分开保存。
- 每个目标记录可选字段 `periodId`，取值为周期起始月，如 `2026-09` 表示 2026 年 9–10 月。KR 跟随所属目标，不单独记录周期。
- 页面打开时定位到当天所在周期；切换周期只是视图状态，不写入同步数据。新增、排序、删除都带上当前周期，不会误改其他周期。
- 目标可用行内的 ← / → 结转到相邻周期，KR 一并带走，顺序保留。
- 1.0.0 版本产生的旧目标没有 `periodId`，会作为“未分期”单独列出，需点击“归入当前周期”显式归入；插件不会按设备时间自动改写旧数据。文档版本号保持 1，旧版插件读取带 `periodId` 的数据时仍能正常显示。

### 历史周期自评

- 只有已结束的周期（早于当天所在周期）会在每个目标下方显示自评表单：0–100% 的分数滑块和一句话评论（最多 200 字）。当前和未来周期不显示，避免过早打分。
- 保存后目标写入可选字段 `review: { score, comment }`，`score` 为 0–100 的整数，`comment` 为去掉首尾空白的字符串。标题行显示分数，评论显示在 KR 列表下方；可反复修改覆盖。
- 自评动作同样带周期范围，只能改当前查看周期内的目标。目标结转到其他周期时自评随目标保留。
- 文档版本号仍为 1，旧版插件读取带 `review` 的数据时照常显示 O 和 KR。

`manifest.json` 中的 `id: okr` 是持久化命名空间，必须保持稳定。发布时同步更新 `manifest.json` 和 `package.json` 的版本。

宿主必须支持 `persistedDataChanged` hook；主项目中修复的保存完成时机逻辑仍由主项目维护。仅安装 ZIP 不会修复旧宿主的保存逻辑。
